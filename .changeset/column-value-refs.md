Columns are stored by their result-pool column ids: the dataset and the condition, gate and sort-fraction columns. The gates of the gate order, the unsorted input and the excluded conditions are stored as column value references of the gate and condition columns, so the block that produced the metadata knows which of its values this block uses; the ranks the workflow receives are keyed by the same references. The model finds columns, builds the options of every column and value picker and reads the sample names through the column collection API instead of the deprecated result pool API, the values are read by the model instead of fetched by the settings panel, and the workflow takes every column through a column bundle. The snapshots of the gate and condition columns' values, written when a column is picked, are stored as column value references of that column too.
Opening a project created before this change keeps its dataset, and clears its condition, gate and sort-fraction columns, the gate order, the unsorted input, the excluded conditions and the value snapshots, since they were stored by ids anchored to the dataset and as plain values, which name no producing block; they have to be picked again before the block runs. The initialization params of the kind carry the same ids and references, the value snapshots included, so templates made for an earlier version of the kind cannot be applied.
Gates, the input and excluded conditions that are no longer among the values of their column stay selected and are marked as not available instead of being removed silently, with a tooltip naming the block that was to provide them, as a link to it, and what went wrong. Picking another gate or condition column still resets the values picked in it and rewrites its snapshot. No check that disables the run is removed: a gate column with no values, a gate or an input the gate column does not carry, and every condition excluded still disable it.
